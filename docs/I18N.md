# 多语言（i18n）

用户端（`frontend/`）与管理端（`admin/`）都支持 **简体中文（zh）/ 英文（en）/ 越南语（vi）**。两个应用各自带一份结构相同的 `src/i18n/`（互不引用），下文以用户端为例，差异见「管理端」一节。

## 目录

```
frontend/src/i18n/
  detect.ts        语言类型、浏览器识别（zh*/vi*/其它→en）、localStorage 覆盖、日期格式
  context.tsx      I18nProvider / useI18n()
  translate.ts     tr()：非 React 场景取当前语言文案
  rich.tsx         tRich()（把 {name} 换成 JSX）、tMarkup()（**粗体** 与 `代码` 标记）
  lookup.ts        点路径取值 + {var} 插值
  locales/
    zh.ts en.ts vi.ts        桶文件，展开各 domain
    {zh,en,vi}/<domain>.ts   按业务域拆分的文案（同一 domain 三种语言键必须一致）
```

`zh` 是类型来源（`Messages = typeof zh`），`en` / `vi` 以 `as unknown as Messages` 挂载，**TypeScript 不会检查它们缺键**，必须靠下面的检查脚本。

## 怎么用

| 场景 | 写法 |
| --- | --- |
| 组件渲染 | `const { t } = useI18n()` → `t('ns.key', { n })` |
| 组件里已有变量叫 `t` | `const { t: tx } = useI18n()`（本仓库约定 `tx`） |
| `useEffect` / `useCallback` / 事件回调 / 工具函数 | `import { tr } from '.../i18n/translate'` → `tr('ns.key')`（调用时读取当前语言，不会因闭包停留在旧语言） |
| 译文里要嵌 `<strong>`、`<code>`、链接 | `tRich(t('key'), { name: <strong>…</strong> })` 或译文里写 `**粗体**` / `` `代码` `` 再用 `tMarkup()` |

## 约定（踩过的坑）

1. **不要把翻译后的文案存进模块级常量**——常量在导入时求值，语言就固化了。用 `labelKey: 'ns.key'` 存键、展示时再 `tx(labelKey)`；或用 getter：`{ id, get label() { return tr('ns.key') } }`（词库/预设这类被到处引用的常量用这种，见 `lib/dramaCameraLexicon.ts`）。
2. **状态值/比较用 id，不要用展示文案**。例如 `PillTabs` 传 `items`（值）+ `labels`（展示名）；输入方式用 `'theme' | 'script'`，不要用「一句话主题」。
3. **保持中文、不翻译的内容**：
   - 写进脚本或被解析的语法标记：`【字幕…】`、`【对白…】`、`空镜：`、`@duration:N`、`场 N` 等（`lib/dramaEpisodeScriptValidate.ts`、`outlineScriptPreview.tsx`、词库的 `insert`）。
   - 发给模型的提示词、与后端返回串匹配的正则（`dramaGenError.ts`、`billingError.ts`、`includes('合成成片')` 等）。
   - 中文作键的映射（`tools.chips`、模板分类 `category`、`CATEGORY_ORDER`、`TemplatesPage` 的「全部」哨兵值）。
   - 科普「灵感示例」正文（成片语言为中文）。
   - 写入后端的兜底名（如音色绑定的 `label: '音色'`），避免数据随界面语言变化。
4. 队列任务的 `subtype`（`'分镜视频'` / `'画布视频'`）是被 `===` 比较的标识，展示时经 `VIDEO_SUBTYPE_LABEL_KEY` 再翻译。
5. 后端返回的报错 `detail` 目前仍是中文短句，前端不翻译。

## 新增/修改文案

1. 在对应的 `locales/{zh,en,vi}/<domain>.ts` 三处同时加同名键（占位符 `{name}` 三处一致）。
2. 新 domain：新建三个文件并在 `locales/{zh,en,vi}.ts` 桶文件里展开。
3. 跑检查：

```bash
cd frontend && npm run i18n:check   # 三语键一致、占位符一致、源码里 t('a.b') / 'ns.key' 字面量键均存在
npx tsc -b
```

`i18n:check` 会编译三个桶文件再比对，并扫描源码里的 `t(` / `tr(` / `tx(` 与 `'<顶层键>.xxx'` 字面量，键写错时页面只会显示键路径本身，不会报错，所以这个检查是唯一的兜底。

## 新增一种语言

1. `detect.ts`：`Locale` / `LOCALES` / `LOCALE_HTML` / `LOCALE_DATE` / `isLocale` / `localeFromBrowser` 各加一项。
2. 复制 `locales/en/*.ts` 为新语言目录并翻译，`locales/<lang>.ts` 桶文件展开，`messages.ts` 注册。
3. `LanguageSwitch.tsx` 加按钮文案键（`nav.langXx`，三语都要有）。
4. 跑 `npm run i18n:check`。

## 管理端（`admin/`）

- 结构与用户端一致：`admin/src/i18n/`（detect / context / translate / lookup / messages / rich / locales）。语言存 `localStorage` 键 `printfilm.admin.locale`，顶栏右上角有 `中 EN VI` 切换。
- 代码风格沿用管理端（双引号、分号、`@/i18n` 别名导入）；组件里用 `const { t: tx } = useI18n();`。
- `lib/statusLabels.ts`、`lib/dramaLabels.ts` 等「值 → 标签」常量用 getter（`get DRAFT() { return tr("status.draft"); }`），调用方无需改动；侧栏 `navGroups` 同理。
- 日期统一用 `formatDateTime()`（`toLocaleString(<当前语言>)`），不要再直接 `new Date(x).toLocaleString()`。
- 检查：`cd admin && npm run i18n:check`。
- 模板编辑里「分类」输入框的示例 `真人感,电影感,商业` 是后端分类值，保持中文。

## 已知限制

- 用户协议 / 隐私政策（`lib/legalContent.ts`）与 `/method` 落地页（`lib/methodLanding.ts`）没有越南语译本，`vi` 回退英文。
- `lib/helpContent.ts`、`lib/homeLanding.ts` 里的中文常量已被 `help.*` / `home.*` 文案取代，目前无引用。
- 后端错误串、模板名称/描述（来自数据库）不随界面语言变化。
- 管理端里由后端返回的中文错误、枚举值（如分类）同样不翻译。
